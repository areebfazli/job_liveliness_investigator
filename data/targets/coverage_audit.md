Generated by `scripts/audit_targets.py` against the live Greenhouse / Ashby / Lever
public job-board APIs, using the 78-company candidate list at
`data/targets/candidates_raw.csv`. Full per-row results (including any
failures) are in `data/targets/audit_results_full.csv`; the verified subset

(`role-liveness-investigator-coverage-audit/0.1 (contact: uzair.khan@progbid.com)`),

## Tenant / domain divergences

`website_domain` (used as `company_id`) is normalized (lowercase, no
protocol/path). Several candidates have an ATS `tenant` string that is
**not** a trivial derivation of that domain. These are legitimate,
intentional divergences (companies frequently pick a different/shorter
slug when they set up their ATS board) and should be tracked as such —
not treated as data-entry errors:

| Company | website_domain | ats | tenant | Note |
|---|---|---|---|---|
| Grafana Labs | grafana.com | greenhouse | grafanalabs | tenant adds "labs" suffix |
| Miro | miro.com | greenhouse | realtimeboardglobal | tenant is Miro's old company name ("RealtimeBoard") |
| Scale AI | scale.com | greenhouse | scaleai | tenant appends "ai" |
| Ironclad | ironcladapp.com | ashby | ironcladhq | tenant uses "ironcladhq" vs. app domain |
| Clay | clay.com | ashby | claylabs | tenant is the legal/company-name form ("Clay Labs") |
| Mistral AI | mistral.ai | ashby | mistral.ai | tenant is the literal domain string (unusual — most tenants are bare slugs) |
| Hive | thehive.ai | lever | hive | tenant drops the "the" prefix |
| Level AI | thelevel.ai | lever | levelai | tenant drops "the" and the dot |
| Sierra | sierra.ai | ashby | **Sierra** (capitalized) | tenant is case-sensitive; differs from domain by capitalization only |

None of these caused API failures — the audit script uses the `tenant`
value verbatim from the candidate CSV, so the divergence is purely
informational/traceability, not a bug.

## Surprising findings

- **No failures at all.** All 78 candidates resolved cleanly on the first
  pass; the 40-target retry/investigation contingency in the task was not
  needed.
- **No zero-job boards.** The smallest verified boards were Pinecone
  (ashby, 6 open jobs), PostHog (ashby, 9), JustWatch (lever, 10), Deputy
  (lever, 11), and Airtable (greenhouse, 16) — all comfortably non-empty.
- **Sierra's Ashby tenant is capitalized** (`Sierra`, not `sierra`), unlike
  every other tenant slug in the list, which are all lowercase. Ashby's
  API is apparently case-sensitive here (a lowercase `sierra` would need
  to be verified separately if ever hand-typed), so this is worth keeping
  exactly as-is in any resolver code that treats tenants as case-sensitive
  identifiers.
- **Mistral AI's tenant is its own domain string** (`mistral.ai`), unlike
  every other Ashby tenant which is a short slug — the ATS board URL is
  literally `https://jobs.ashbyhq.com/mistral.ai`. This is a real quirk of
  how Mistral configured their board, not a data-entry artifact.
- **Miro's tenant reveals its former identity** — `realtimeboardglobal`
  is a holdover from Miro's original name, RealtimeBoard, before its 2019
  rebrand. No functional issue; just a historical fingerprint in the URL.
- No evidence of any candidate having migrated ATS providers was found —
  all 78 tenants resolved on the ATS listed in the candidate CSV with no
  redirects or 404s that would suggest a stale/migrated board.
- Highest open-job counts: Elastic (greenhouse, 365), Harvey AI (ashby,
  348), Okta (greenhouse, 313), Palantir (lever, 310), Brex (greenhouse,
  282).

## Wayback capture spot-check

Ten verified boards were sampled (spread across all three ATS types,
proportional to their share of the 78 verified targets, with at least 2 of
each ATS type) and queried against the Wayback Machine CDX API at 0.5
req/s via `scripts/wayback_spotcheck.py`. Full per-company results are in
`data/targets/wayback_spotcheck_results.csv`.

| Company | ATS | Tenant | Captures (of 5 requested, `from=2025`) |
|---|---|---|---|
| Ramp | ashby | ramp | 5 |
| Linear | ashby | linear | 5 |
| Modal Labs | ashby | modal | 5 |
| Affirm | greenhouse | affirm | 5 |
| Airbnb | greenhouse | airbnb | 5 |
| Airtable | greenhouse | airtable | 5 |
| Asana | greenhouse | asana | 5 |
| Palantir Technologies | lever | palantir | 5 |
| Binance | lever | binance | 5 |
| Included Health | lever | includedhealth | 5 |

**Capture density per ATS: greenhouse 4/4, ashby 3/3, lever 3/3 sampled had
captures** — every one of the 10 sampled boards has archived snapshots
since 2025, and all hit the `limit=5` cap, meaning each has at least 5
captures in-window (the true count may be higher; this script only
requests the first 5 per host).

**Note on transient failures — throttling, not absence:** across three
querying passes against these same 10 boards (an initial run, a manual
verification pass, and a rerun to validate the script's retry logic), the
Wayback CDX API produced a mix of clean 200s, outright timeouts, and (once
request volume picked up within a short window) HTTP 429s on `lever.co`
URLs specifically. Every one of these 10 boards was confirmed to have 5/5
captures on at least one clean pass — the failures were transient
server-side throttling/slowness, not missing archive coverage, and are
recorded here as coverage gaps rather than zero-capture results. This is
a concrete, first-hand illustration of the PLAN.md principle that a
throttled or failed Wayback query must be treated as a coverage gap, never
as evidence of absence: naively trusting a single request per host would
have produced a false "lever.co has poor Wayback coverage" conclusion,
when the true cause was CDX rate-limiting under repeated querying from one
IP. `scripts/wayback_spotcheck.py` retries once automatically on
timeout/connection error (mirroring `audit_targets.py`), but a 429
response is not currently retried — a production backfill client should
add backoff-and-retry on 429 specifically, and should keep genuinely wider
gaps between requests than the 0.5 req/s used here for a 10-board spot
check, since real CDX rate limits appear tighter than that under burst
conditions.

This is a rough spot-check only (10 of 78 boards), not a full backfill —
useful as a directional signal for how much Wayback history exists per
ATS provider, not a guarantee of coverage for any specific company.
